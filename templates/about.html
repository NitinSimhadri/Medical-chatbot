About MediBot AI

Your AI-powered medical information companion

What is MediBot AI?

MediBot AI is an advanced conversational healthcare assistant that leverages retrieval-augmented generation (RAG) combined with large language models to provide comprehensive medical information and guidance. By searching through a curated database of medical documents, our AI delivers evidence-based responses tailored to your health-related queries.

Service Details

Below is a short description of each service available in MediBot AI so you know what each feature does and how to use it.

AI Chat

Conversational assistant that answers general health questions. Uses heuristics for quick replies, and a RAG pipeline (when configured) for evidence-backed answers.

Symptom Checker

Guided symptom intake that suggests possible conditions and next steps. Intended for informational use and not a diagnosis.

Prescription Analysis

Upload prescription images to extract text via OCR, identify medication lines, and provide plain-language explanations and likely indications. OCR uses local Tesseract if available, with OCR.space as a configurable fallback.

Medication Tracker

Store and view your current medications, set reminders, and track adherence over time. Integrates with the Reminder system to notify you by email.

Reminders & Email Notifications

Create medication or appointment reminders. The system can send email notifications using configured SMTP credentials; reminders are persisted locally and can be encrypted at rest.

Appointment Booking

Search for nearby clinics (Google Places integration) and save booking details. Location search uses geocoding + expanding radius fallback for coverage.

BP & Heart Rate / Vitals / BMI Tools

Useful calculators and trackers for common health metrics like blood pressure, heart rate, BMI, and other vitals. Helps you monitor trends over time.

Skin Analysis

Upload skin images for automated analysis (image classification). Uses hosted Hugging Face models when configured and local model fallback where available. Provides guidance and suggests when to seek specialist care.

Report Generator

Create simple summaries and printable reports from your stored data and chat history for sharing with healthcare providers.

Health Vault

The Health Vault is your personal, secure storage area for medical records, prescriptions, lab reports, and notes. Records saved here are tied to your account, stored locally on the server, and can be encrypted at rest when you set a FERNET_KEY. Think of it as a private file cabinet where you keep documents you may want to review or share with clinicians.

Health Analytics

Health Analytics processes time-series and summary data (vitals, weight, activity, medication adherence) to generate trends, charts, and insights. It aggregates measurements from your tracked entries to surface patterns (for example: rising blood pressure over weeks, weight change, or adherence gaps) and provides visual reports and simple suggestions. Analytics uses data that you (or connected tools) record — it does not automatically access other files in your Health Vault unless you explicitly export or link them.

Chat History

Your recent conversations with the bot are stored locally so you can review past guidance and follow up on previous recommendations.

How We Protect Your Data

Your privacy and the security of your medical information are a top priority. Below we summarise the measures implemented in MediBot AI to protect user data.

  • Encryption at rest: Sensitive JSON stores (users, reminders, appointments, histories) can be encrypted using Fernet symmetric encryption when a secure key is provided via the FERNET_KEY environment variable. If enabled, files are stored encrypted on disk.
  • Atomic writes & backups: All app data is written atomically and timestamped backups are created in the backups/ folder to reduce the risk of data loss during crashes or interruptions.
  • Least privilege & access control: Endpoints that operate on personal data (uploading prescriptions, booking, reminders) require authentication. Session cookies are used to isolate user data.
  • Network security: We recommend running MediBot behind HTTPS (TLS) and using firewall rules to limit exposure. Do not run the app in production without HTTPS.
  • Secrets management: API keys and passwords are loaded from environment variables (.env) and not checked into source control. Keep your FERNET_KEY, SMTP credentials, and any LLM/API keys secret and backed up securely.
  • Minimal external sharing: The app uses free, public sources (openFDA) for drug information and only contacts external services when needed (OCR.space when configured, Google Maps for bookings if a key is provided). We do not share user-uploaded prescription images to third parties unless explicitly configured; if OCR.space is enabled the image bytes are sent to that API only as a fallback and only if a key is present.
  • Data retention & user control: Data is stored locally in JSON files; users can request deletion (the developer can remove records). We recommend adding a user-facing delete/export feature and a retention policy for production deployments.
  • Operational security: Keep the server OS and Python dependencies up to date, and rotate the FERNET_KEY and SMTP credentials periodically.

Important: If you enable encryption by setting FERNET_KEY, losing that key will make encrypted files unrecoverable. Store the key in a secure secrets manager or offline backup.

Why Use MediBot AI?

  • Evidence-Based Information: Responses are backed by curated sources and public datasets (for drug labels we use openFDA where available).
  • RAG + LLM: The app uses retrieval-augmented generation (RAG) when configured (Groq/Pinecone or local RAG), falling back to local models or heuristic responses so it works without paid APIs.
  • Comprehensive Tools: From calculators and clinic search to prescription OCR and medication explanations.
  • User-Friendly Interface: Clean, responsive UI with accessible workflows for uploading prescriptions, setting reminders, and booking appointments.
  • Free-First Design: Core functionality uses free sources (openFDA, local models, local inference). Optional integrations (cloud-hosted LLMs) are available but not required.
  • Privacy by design: Sensitive data is stored locally, encrypted when enabled, and not repackaged or sold.
